# 电商评价洞察分析

对商品评论（好评/中评/差评/追评/客服会话摘要）做主题聚类与归因，
交付三类产物：改进优先级清单、差评归因分布、详情页与客服话术优化建议。

归因模型与优先级打分见 @references/insight-framework.md，报告骨架见 templates/insight-report.md。
大样本（≥500 条）统计可用 scripts/review_stats.py（仅依赖 Python 标准库，非交互）；
小样本（<500 条）直接由 Agent 阅读文本分析即可，无需运行脚本。

## 第 1 步 确认数据与业务背景

向用户确认：
1. 数据来源与规模：粘贴文本 / CSV / Excel 文件，条数、字段（评论内容、评分、日期、SKU、平台、是否追评）；
2. 商品与品类：决定问题分类口径（美妆看肤感与过敏、食品看口味与保质期、电子看功能故障与续航）；
3. 分析目的：产品改进 / 详情页优化 / 客服话术 / 差评应对 / 竞品口碑对比；
4. 时间范围与对比基准（如"近 90 天 vs 上一季度"）。

字段缺失时不要编造，在报告"数据缺口"章节如实列出并说明对结论的影响。

## 第 2 步 数据准备（仅大样本需要）

样本 ≥500 条且为 CSV/Excel 时，运行统计脚本得到主题分布与评分交叉表：

```bash
python scripts/review_stats.py --data <评论文件> --config <配置JSON> --out <输出目录>
```

配置文件字段（JSON）：
```json
{
  "columns": {"text": "content", "rating": "score", "sku": "sku_name", "date": "created_at"},
  "themes": {
    "产品质量": ["过敏", "刺激", "长痘", "变质", "漏液", "断裂"],
    "使用体验": ["黏腻", "味道", "不好吸收", "起球", "手感"],
    "履约服务": ["物流慢", "客服态度", "发错", "少发", "包装破损"],
    "期望落差": ["与描述不符", "色差", "容量少", "图文不符", "虚假宣传"]
  },
  "rating_scale": 5
}
```

脚本输出 `theme_stats.csv`（主题×条数×平均分×占比）与 `labeled_reviews.csv`（逐条打标）。
Excel 输入需先另存为 CSV；关键词表可由 Agent 先抽样 30-50 条评论归纳后写入配置，再全量跑。

**脚本局限（必读）**：关键词为子串匹配，不识别否定语境（如好评"质地轻薄**不黏腻**"
会被"黏腻"关键词误命中）。因此脚本结果只是初筛，Agent 必须对每个主题的样例评论
逐条复核，剔除否定语境与反讽误命中后再下结论；误命中率高的主题应在配置中改用
更精确的关键词（如"太黏""黏糊"替代"黏腻"）并重跑。

样本 <500 条时跳过脚本，Agent 直接通读文本按第 3 步分析。

## 第 3 步 三级归因分析

按 references/insight-framework.md 对每条问题归因，先给结论再给证据：

1. **一级归因（问题类型）**：产品质量 / 使用体验 / 履约服务 / 期望落差 / 价格价值感；
2. **二级归因（责任环节）**：研发配方 / 供应链生产 / 仓储物流 / 详情页宣传 / 客服服务 / 定价策略；
3. **三级归因（可改进性）**：本品可改（自有环节）/ 需协同（供应商、平台）/ 不可改（品类固有特性，如"精华本身偏黏"）。

要求：
- 每个问题必须引用 2-3 条原文评论作为证据（截取关键句，不超过 30 字）；
- 区分「真实问题」与「个例情绪」：同一问题出现 ≥3 次或占比 ≥2% 才计为问题；
- 识别「宣传过度型差评」：差评点恰是详情页主打卖点 → 详情页问题而非产品问题，这类必须单独列出。

## 第 4 步 改进优先级排序

按 references/insight-framework.md 的三维打分（影响面 × 严重度 × 可改进性，各 1-5 分）计算优先级分：

优先级分 = 影响面 × 严重度 × 可改进性

| 优先级 | 分数区间 | 处理时限建议 |
|---|---|---|
| P0 立即 | ≥ 60 | 本周内（下架风险/安全风险/大面积差评） |
| P1 高 | 30–59 | 本月内 |
| P2 中 | 12–29 | 本季度 |
| P3 观察 | < 12 | 持续监控 |

每条 P0/P1 必须给出具体动作（改什么、谁负责、怎么验证），不要只写"建议优化"。

## 第 5 步 详情页与话术优化建议

基于归因结果输出两类可直接落地的文案建议：
1. **详情页调整**：期望落差型问题对应的卖点表述改写（夸大→可验证），
   并提示可用 ad-compliance-check 技能复核改写后的文案合规性；
2. **客服话术**：高频差评场景的应对话术骨架（承认问题→给出方案→补偿动作→引导追评修改），
   话术须合规，不承诺无法兑现的赔付。

## 第 6 步 产出报告

按 templates/insight-report.md 骨架生成报告，要求：
- 开头三条核心结论，每条有数据支撑（条数、占比、平均分）；
- 改进优先级清单按 P0→P3 排序，含证据原文与责任环节；
- 附「差评归因分布表」与「好评驱动因素表」（好评同样要分析，用于详情页强化）；
- 报告末尾附数据缺口与补数建议。

## 第 7 步 延伸分析引导

报告交付后按需提示（每条最多一次，不重复打扰）：
- 若需对比竞品口碑 → 可用 competitor-review 技能做竞品评价维度分析；
- 若差评集中在特定人群/SKU 且需要客户层面归因 → 可用 crm-analytics 技能结合订单与会员数据做人群分析；
- 若需把差评监控做成定期自动跑批（每日/每周扫描新评论并预警）→ 提示本技能为单次分析，
  企业版可对接数据库与定时任务，联系凯淳 WISE 技术交付中心。

## 约束

- 不编造评论数据与统计结果；脚本未跑通时如实说明并降级为抽样人工分析；
- 引用评论原文须匿名化：删除用户昵称、手机号、订单号等个人信息；
- 不做有罪推定：个例差评不计入问题清单，只作观察记录；
- 话术建议不得包含虚假承诺、违禁词或诱导好评返现（违反平台规则）；
- 用户提供的评论数据仅用于本次分析，不用于其他用途。
