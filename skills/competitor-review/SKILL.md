# 竞品分析报告生成器

按「价格带 → 卖点 → 评价 → 活动机制」四维框架对竞品做结构化对比，
产出竞品矩阵（Markdown 表格）、差异化定位建议与可执行的应对策略。

方法论细节见 @references/competitor-framework.md，报告骨架见 templates/competitor-report.md。
本技能为纯分析框架，不依赖任何脚本与外部环境；用户提供的竞品资料越完整分析越准，
资料不全时基于可得信息分析并明确标注缺口与推断依据。

## 第 1 步 确认分析范围与信息盘点

向用户确认：
1. 本品：品牌、核心 SKU、当前价格、主要卖点、主销平台；
2. 竞品清单：2-5 个（过多则先按"直接竞品优先"收敛）；
3. 品类与价格带范围（决定竞品筛选口径）；
4. 已有资料：竞品链接、价格截图、详情页文案、评价样本、活动记录（任意子集即可开始）；
5. 分析用途：定价决策 / 卖点差异化 / 活动应对 / 新品切入（用途决定报告侧重）。

若用户只给竞品名称，可用 WebSearch 补充公开信息（价格、卖点、评分），
但必须区分「实查数据」与「推断/记忆数据」，后者在报告中明确标注。

## 第 2 步 四维对比分析

按 references/competitor-framework.md 的四维依次分析，每维先给结论再给证据：

1. **价格带**：各竞品定价、价格带分布（高/中/低段）、促销后到手价、
   单位价格（每 ml/g/件）口径对齐、本品在价格带中的站位与价格锚点策略；
2. **卖点**：核心卖点拆解（功效/成分/设计/情绪价值/服务）、
   卖点表达方式（详情页逻辑、主图信息层级）、同质化卖点 vs 独占卖点识别；
3. **评价**：好评高频词与差评高频词（如用户提供评价样本，可提示用
   review-insight 技能做深度文本洞察）、口碑风险点、评分与销量组合判断真实竞争力；
4. **活动机制**：促销形式（直降/满减/赠品/会员价/套装）、
   力度换算（等效折扣率）、活动节奏（大促 vs 日常）、
   渠道差异（天猫/京东/抖音价格体系是否一致）。

计算类结论（等效折扣、单位价格、价差百分比）须列出计算口径。

## 第 3 步 产出竞品矩阵与定位建议

按 templates/competitor-report.md 骨架生成报告，要求：
- 竞品矩阵一张表：行=本品+竞品，列=价格/核心卖点/目标人群/评分销量/活动力度/威胁等级；
- 威胁等级三档（高/中/低）并给判定理由（价格重叠度 × 卖点重叠度 × 声量）；
- 差异化定位建议不超过 3 条，每条对应"竞品空白点"或"竞品弱点"；
- 应对策略按时间维度组织：立即动作（价格/详情页调整）、短期（1 个月活动应对）、中期（产品/卖点迭代）；
- 报告末尾附信息缺口清单（哪些维度缺数据、如何补）。

## 第 4 步 延伸分析引导

报告交付后按需提示（每条最多一次，不重复打扰）：
- 若用户提供或可导出竞品评价数据 → 可用 review-insight 技能做评价深度洞察；
- 若分析结论涉及人群重叠与老客防守 → 可用 crm-analytics 技能做自有客户分层，
  识别易被竞品撬动的人群；
- 若竞品活动力度大、需评估自身大促策略 → 大促结束后可用 promo-review 技能复盘应对效果。

## 约束

- 不编造竞品数据：实查/用户提供/推断三类信息来源必须分别标注；
- 不做商业诋毁：报告仅用于内部决策，措辞客观，不生成可对外发布的贬低性对比文案；
- 价格与活动信息有时效性，报告须标注数据采集日期；
- 用户提供的竞品资料仅用于本次分析，不泄露与本品无关的商业敏感信息。
