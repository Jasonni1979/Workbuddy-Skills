# 平台字段映射与口径规则

> 覆盖天猫（生意参谋）、京东（商智）、抖音（电商罗盘）、拼多多（商家后台）常见导出报表。
> 表头因店铺/版本不同会有差异，映射前必须用 `--inspect` 核对实际表头，本表为起点而非终点。

## 一、标准字段定义（合并表 schema）

| 标准字段 | 含义 | 必填 | 口径默认值 |
|---|---|---|---|
| date | 统计日期 YYYY-MM-DD | 是 | 按平台报表自然日 |
| platform | tmall/jd/douyin/pdd/other | 是 | 配置指定 |
| sku | 商品/SKU 编码 | 否 | 平台商品ID |
| sku_name | 商品名称 | 否 | 平台商品标题 |
| gmv | 支付金额（元） | 否 | 支付口径，含未发货、不含取消 |
| qty | 支付件数 | 否 | |
| refund | 成功退款金额（元） | 否 | 单列不扣减 |
| uv | 访客数 | 否 | 店铺/商品访客去重口径 |
| orders | 支付订单数 | 否 | |
| net_gmv | 净销售额 = gmv − refund | 脚本自动算 | |

## 三、口径决策默认值（须与用户确认后定稿）

| 决策点 | 默认 | 备选 | 影响 |
|---|---|---|---|
| GMV 口径 | 支付金额 | 成交金额（剔取消）/ 结算金额 | 大促期差异可达 5-15% |
| 退款处理 | 单列 refund，net_gmv 另算 | 直接扣减 | 影响毛利分析 |
| 金额单位 | 元 | 分（/100） | 京东部分接口为分 |
| 含税 | 含税（平台口径） | 不含税（/1.13 等） | 财务对账时才转 |
| 跨平台同款 | 按 sku 编码 | 名称模糊匹配 / 用户 spu_map | 编码体系不同时必须用 spu_map |
| uv 跨平台相加 | 不加总（口径不同） | 仅同平台内加总 | 抖音曝光口径与货架访客口径不可加 |
| 时间粒度 | 保留原始粒度 | 统一聚合到日 | 订单级文件聚合到日时注明 |

## 四、数据质量检查阈值

| 检查项 | 告警阈值 | 处理 |
|---|---|---|
| 日期解析失败率 | >1% | 补 date_format 重跑 |
| 关键字段空值率（gmv/date） | >0 | 逐条列出行号样例 |
| 重复键（date+sku） | >0 | 确认是否多报表重叠，去重或改 dedup_keys |
| 金额负数 | 任意 | 退款冲正 or 单位错误，逐条确认 |
| 金额 >1000 万单行 | 任意 | 疑似单位"分"或汇总行混入 |
| 合并后行数 < 各文件之和 | 差额=去重+日期失败 | 报告必须解释差额 |

## 五、常见坑

1. **汇总行混入**：平台导出常带"总计"行，日期为空或为"合计"→ 日期解析失败自动过滤，但要在报告确认过滤数；
2. **多 sheet Excel**：只取目标 sheet，另存 CSV 时确认 sheet 名；
3. **GBK 编码**：京东/拼多多部分导出为 GBK，--inspect 会自动试 utf-8-sig/gbk/utf-8；
4. **千分位逗号**：金额带 "1,234.56"，脚本已去逗号；
5. **直播渠道重复计**：抖音罗盘分渠道导出时，渠道行之和=总计行，切勿两者都合并；
6. **退款跨期**：8 月订单 9 月退款，按退款成功日期归期（平台口径），跨期差异在报告注明。
