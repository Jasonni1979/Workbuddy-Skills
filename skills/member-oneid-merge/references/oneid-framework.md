# One-ID 合并框架

> 凯淳 WISE 全渠道 CRM 数据治理方法论沉淀。合规前提优先于技术方案。

## 1. 匹配主键策略

| 数据形态 | 匹配能力 | 策略 |
|---|---|---|
| 明文手机号 | 跨源精确匹配 | 内部转 MD5 作键（输出打码），合并置信度=高 |
| 统一 MD5/SHA256 | 跨源精确匹配 | 直接作键（需确认各源加密口径一致：是否含+86、是否小写） |
| 平台密文（天猫/抖音订单密文） | 仅同源内去重 | 不作跨源键；跨源合并需走平台数据合作通道（如天猫数据银行人群包） |
| 无手机号 | 只能模糊匹配 | 姓名+地址+昵称组合，进冲突裁决，不自动合并 |

手机号规范化：去空格/连字符/括号，剥 +86/86 前缀，校验 1[3-9] 开头 11 位；不合规号码不作精确键（避免脏键误合并）。

## 2. 三层匹配漏斗

```
第1层 同源去重      同一文件内同手机号 → 保留最新，消费额按 config（sum/max）
第2层 跨源精确匹配   手机号键一致 → 自动合并（高置信）
第3层 跨源模糊匹配   姓名一致 + 地址相似度≥阈值 → 候选对进冲突裁决（中置信，不自动合并）
剩余                未匹配记录单独成 One-ID（低置信，后续数据补充后再合并）
```

地址相似度：字符二元组 Jaccard（无分词依赖）。阈值语义：
- ≥0.85：地址基本一致（同门牌），姓名一致时建议合并；
- 0.6-0.85：同小区/同路不同门牌 → 人工确认（可能家庭成员或搬家）;
- <0.6：不产生候选对。

## 3. 冲突裁决规则

| 情形 | 裁决 | 依据 |
|---|---|---|
| 姓名一致+相似度≥0.85+等级/注册时间互相佐证 | 合并（Agent 裁决，标记留痕） | 双证据链 |
| 姓名同音不同字（张伟/张薇）+地址一致 | 人工确认 | 可能录入口误，也可能夫妻 |
| 姓名一致+同小区不同门牌 | 人工确认 | 家庭成员概率高，按业务口径定 |
| 昵称一致但姓名地址均缺 | 人工确认 | 昵称撞名率高，不可自动合并 |
| 姓名不一致+仅地址相似 | 拒绝 | 合租/代收点场景 |
| 同一手机号 >5 个姓名 | 单独标记 | 羊毛党/代购/公用号，不算 One-ID 合并质量 |

家庭户口径：品牌做"家庭户"运营（母婴/食品常见）时，同手机号+同地址可归户；做个人 CLV 时保守拆分。口径由业务方确认，未确认时默认个人口径（不合并）。

## 4. 字段合并优先级（config.field_priority）

| 字段 | 默认规则 | 说明 |
|---|---|---|
| name | 渠道优先级列表 | 门店实名 > 平台收货人 > 昵称 |
| level | 渠道优先级列表 | 取业务主渠道等级；多等级并存时主表保留全渠道等级列 |
| total_spend | sum | 全渠道累计消费（跨渠道 CLV 的基础）；同源内去重阶段按 max 防重复计数 |
| register_date | min | 最早注册时间=客龄起点 |
| address | 渠道优先级列表 | 门店/自建商城地址更新更及时 |
| nickname | 保留全部 | 各渠道昵称并列（触达话术按渠道取用） |

缺失不猜测：来源渠道没有的字段留空，不用其他渠道值外推填充。

## 5. 质量指标口径

| 指标 | 定义 | 健康参考 |
|---|---|---|
| 合并率 | 1 − One-ID数/源记录数 | 渠道重合高的品牌 20-50% |
| 跨渠道重合率 | ≥2 渠道的 One-ID 占比 | 全渠道成熟品牌 ≥15%；<5% 说明渠道人群割裂或手机号口径不通 |
| 冲突率 | 候选对数 / One-ID 数 | <10% 可人工消化；>20% 先收紧阈值再跑 |
| 字段缺失率 | 按渠道×字段矩阵 | 决定下游分析可用字段清单 |
| 低置信占比 | 未匹配单独成行占比 | <30%；过高说明源数据手机号可用性差 |

## 6. 合规检查清单（合并前必过）

1. 各渠道隐私政策/用户协议是否覆盖"为提供服务进行会员数据合并使用"；
2. 数据出域评估：平台导出数据的二次使用是否违反平台规则（尤其天猫/抖音）；
3. 最小必要：合并只取运营必需字段，身份证号/精确位置等敏感字段不并入主表；
4. 存储安全：主表含匹配键（MD5），提示加密存储与访问控制；流转展示用打码版；
5. 用户权利：保留删除/更正通道，触达退订状态同步到 One-ID 层（联动 private-domain-sop 熔断名单）；
6. 无授权基础时：停止合并，提示法务评估替代方案（平台侧人群包合作、门店侧扫码入会补采集）。

## 7. 常见坑

1. 加密口径不一致：A 源 MD5(明文)、B 源 MD5(带+86) → 键永不相交，合并率异常低。先统一规范化再加密；
2. 拿模糊匹配直接入库：姓名撞名+地址相似≠同一人，自动合并会污染 CLV 与触达（错发隐私信息是合规事故）；
3. 消费额跨渠道重复计数：平台订单含门店自提单时 sum 会虚高，先按订单号去重再聚合；
4. 忽略退订/黑名单同步：单渠道退订但 One-ID 层未标记 → 换渠道继续骚扰，熔断失效；
5. 一次性合并当终点：会员数据持续产生，需增量合并机制（企业版服务端 CDP 对接）。
