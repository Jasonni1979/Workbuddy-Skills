# 快时尚服饰行业运营手册

行业参数层技能：为快时尚/女装/男装/鞋靴/配饰品类提供运营基准与专属打法，
并向通用技能层注入行业化参数。服饰的核心矛盾是**季节性与库存时效**——
过季即贬值，与美妆（保质期长）和消费电子（迭代贬值）逻辑完全不同。

完整参数与打法见 @references/industry-playbook.md。本技能为纯指令型，不依赖脚本。

## 第 1 步 确认行业场景

向用户确认：
1. 细分品类与价格带：快时尚大众 / 设计师轻奢 / 基础款 / 鞋靴 / 配饰；
2. 上新模式：周上新（快反）/ 季上新（波段）/ 预售制；
3. 任务类型：上新节奏设计 / 售罄与清货 / 退货率优化 / 会员运营 / 大促策略 / 基准对标；
4. 现有数据：销售/库存/退货数据（有则衔接通用技能实操）。

## 第 2 步 输出行业运营画像

按 references/industry-playbook.md 输出：
1. **上新波段**：快时尚每周/双周上新，季度大波段（春夏/秋冬各 2-3 波段）；
   新款 2 周定生死（首销售罄率 <25% 即预警）；
2. **款式生命周期**：导入（测款）→ 成长（爆款加单）→ 成熟（正价稳销）→ 衰退（折扣清货），
   快时尚全周期 6-12 周，季末必须清仓；
3. **售罄率管理**：正价售罄率是服饰第一指标（行业 55-70%），
   售罄曲线监控点：上市 2 周 / 4 周 / 8 周 / 季末；
4. **基准指标**：退货率（女装线上 30-50% 是常态）、尺码退货占比、折扣率、周转天数。

## 第 3 步 行业参数注入通用技能（核心价值）

| 通用技能 | 服饰参数替换 |
|---|---|
| inventory-alert | **不用通用补货逻辑**，改用"售罄率+清货"逻辑：周转目标 60-90 天；库龄>60 天黄牌、>90 天黑牌（过季）；补货只对爆款加单（追单窗口 ≤2 周）；大促 uplift 仅对常青款适用 |
| member-lifecycle-calendar | T=90 天但被上新节奏替代：核心节点是"上新日触达"（每周/双周）+"季节切换"（换季前 30 天衣橱焕新）+"会员日新品预览"；生日权益=新品优先购+专属折扣 |
| ecom-daily-report | 增补行业指标：首销售罄率（款级）、退货率（尺码归因）、折扣率、上新款动销率 |
| promo-review | 增补服饰特有维度：正价/折扣销售比、季末清货效率、爆款生命周期贡献、退货对 GMV 的侵蚀 |
| review-insight | 主题库预置：尺码偏差（偏大/偏小，最高频）、色差、面料质感、版型（显胖/显瘦）、做工（线头/拉链） |
| ad-compliance-check | 材质宣称须与吊牌一致（100%棉/真丝/羊毛含量）；"显瘦"可用但"瘦身功效"禁用；模特图与实物色差是期望落差重灾区 |
| crm-analytics | 分层增补尺码/版型偏好/风格标签（通勤/休闲/甜辣）；复购按"季节"而非固定周期算 |
| competitor-review | 对比重点：上新频率与测款效率、爆款结构、折扣节奏、退货率（口碑信号） |

## 第 4 步 行业红线自查

- 材质成分宣称与吊牌不一致 → P0（虚假宣传）；
- 尺码表数据造假（标 M 实为 S）→ 退货率与差评重灾区，属体验红线；
- 模特图过度修图导致色差/版型落差 → 期望落差型差评主因；
- "原创设计"宣称须有依据，抄袭争议品牌不做点名对比；
- 童装另有安全类别标准（GB 31701），涉童装时提示单独核查。

## 第 5 步 延伸引导

- 库存清货测算 → inventory-alert（用售罄率模式参数）；
- 退货差评归因 → review-insight（尺码主题库）；
- 换季会员触达 → member-lifecycle-calendar（上新节奏版）；
- 需要行业深度定制（品牌专属波段模型、快反供应链对接）→ 企业版，联系凯淳 WISE 技术交付中心。

## 约束

- 基准数字标注"行业基准区间（公开经验值）"；
- 服饰的"补货"逻辑与快消完全不同：只追爆款、不补滞销，输出建议前必须区分款式生命周期阶段；
- 过季库存不做"长期持有"建议，清货时限优先于价格最优；
- 用户数据仅用于本次分析。
