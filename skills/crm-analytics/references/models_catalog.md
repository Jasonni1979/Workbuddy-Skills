# CRM 分析模型目录（models_catalog）

本文件为每个模型给出：**用途 → 所需逻辑字段 → 计算口径 → 输出指标 → 业务解读**。
`crm_analyze.py` 通过 `config.json` 中的 `columns` 把"逻辑字段"映射到真实列名。

通用约定：
- 日期字段统一解析为 `datetime`；空值按模型说明处理。
- 金额字段按 `params.currency` 标注单位；不做汇率换算。
- `snapshot_date`（分析基准日，默认取数据最新日期）用于计算"距今天数"。

---

## 1. RFM 客户价值分层

**用途**：用最近一次消费(Recency)、消费频次(Frequency)、消费金额(Monetary)三维度给客户打分分层。

**所需字段**
- `customer_id`：客户唯一标识
- `order_date`：订单/交易日期
- `amount`：订单金额（单笔）

**计算口径**
1. 以 `customer_id` 聚合：R = 基准日 − 最近订单日；F = 订单笔数；M = 金额合计。
2. 按 `params.quantile`（默认 4）做分位数打分 1–4（R 反向：越近分越高）。
3. 组合 R/F/M 得 4³=64 档，归并为 8 大客群：
   重要价值(高R高F高M)、重要保持(低R高F高M)、重要发展(高R低F高M)、
   重要挽留(低R低F高M)、一般价值、一般保持、一般发展、一般挽留。

**输出指标**：各客群客户数、占比、平均 R/F/M、累计贡献金额占比（帕累托）。

**业务解读**：高 M 低 R 的"重要挽留"是流失高风险高价值客户，优先触达；
低 R 高 F 的"重要保持"需唤醒复购。

## 2. AARRR 增长漏斗

**用途**：海盗模型，度量用户生命周期五环节转化：获客 Acquisition → 激活 Activation →
留存 Retention → 收入 Revenue → 自传播 Referral。

**所需字段**（事件表，每行一个用户事件）
- `user_id`
- `event`：事件类型，取值建议 `signup` / `activate` / `retain` / `pay` / `refer`
  （也可用日期字段分别给出）
- `event_date`

**计算口径**
- 各阶段人数 = 发生过该事件去重用户数。
- 转化率 = 后一阶段 / 前一阶段；整体转化 = 末阶段 / 首阶段。
- 时间窗由 `params.window`（默认 30 天）界定"激活/留存"判定。

**输出指标**：五阶段人数、逐级转化率、漏损最大环节（瓶颈定位）。

**业务解读**：找出转化最低的相邻环节，针对性优化（如激活低→优化新手引导）。

## 3. AIPL 营销漏斗

**用途**：阿里系营销模型，度量人群资产流转：认知 Awareness → 兴趣 Interest →
购买 Purchase → 忠诚 Loyalty。

**所需字段**
- `customer_id`
- `stage`：阶段标记 `A` / `I` / `P` / `L`（可用 `event_type` 映射）
- `event_date`

**计算口径**
- 各阶段人数 = 曾到达该阶段去重客户数。
- 流转率 = 下一阶段 / 上一阶段；总流转 A→L 比例反映品牌资产健康度。

**输出指标**：四阶段人数、A→I、I→P、P→L 流转率、人均触达阶段数。

**业务解读**：I→P 低说明兴趣转化弱（种草强下单弱）；P→L 低说明复购/会员体系弱。

## 4. CLV 客户生命周期价值

**用途**：测算客户当前与预期终身价值，支撑预算分配。

**所需字段**
- `customer_id`、`order_date`、`amount`

**计算口径（历史法，零依赖）**
- AOV（客单价）= 总额 / 订单数；购买频次 = 订单数 / 存活时长(年)；
- 生命周期 = 首单到末单跨度（或 `params.lifespan` 预设）；
- CLV = AOV × 频次 × 生命周期 × 毛利率(`params.margin`，默认 1)。
- 另给"已发生价值"(历史累计金额) 作为下限参考。

**输出指标**：全量平均 CLV、Top/Bottom 分位、按 CLV 排序的客户清单。

**业务解读**：高 CLV 客户应进入高优先级运营；获客成本(CAC) > CLV 的渠道需止损。

## 5. 留存 / 同期群 Cohort

**用途**：按注册批次看后续各期活跃留存，识别产品黏性问题。

**所需字段**
- `user_id`
- `signup_date`：用户注册/首次日期（决定 cohort 归属）
- `activity_date`：任意活跃行为日期

**计算口径**
- 以 `signup_date` 的"年-月"或"周"分 cohort。
- 第 N 期留存 = 在注册后第 N 个周期仍有 activity 的 cohort 用户占比。
- 输出留存矩阵（cohort × 期数）。

**输出指标**：留存热力矩阵、第 1/3/6/12 期平均留存率。

**业务解读**：留存曲线是否平坦；若快速衰减，说明新用户价值未兑现。

## 6. 流失预警 Churn

**用途**：标记并打分可能流失的客户，优先干预。

**所需字段**
- `customer_id`
- `last_active_date` 或 由 `order_date` 推导"最近活跃日"

**计算口径**
- 流失窗口 `params.churn_days`（默认 90）：距今无活跃 ≥ 该值判为已流失。
- 流失风险分 = 基于"静默天数 / 历史活跃频次 / 历史金额"等归一化加权（0–100）。
- 输出高/中/低 风险分层。

**输出指标**：已流失数、风险分布、高风险客户清单（含最近活跃日、历史金额）。

**业务解读**：高风险高价值客户进入挽留名单；可叠加优惠券/关怀触达。

## 7. 客户分群 K-Means

**用途**：无监督聚类，发现自然客群，补充规则模型的盲区。

**所需字段**：一组数值特征列（如 `r_score, f_score, m_score` 或消费/访问/客单等）

**计算口径**
- 对选定特征做标准化（Z-score）。
- K 由 `params.k`（默认通过肘部/轮廓系数自动选 3–6）决定。
- 输出每个客户的 cluster 标签与聚类中心。

**输出指标**：各簇规模、中心特征画像、簇命名建议（按中心高低）。

**业务解读**：把簇按特征画像命名（如"高频低额""低频高额"），匹配差异化策略。

## 8. 销售漏斗 Sales Funnel

**用途**：观测业务关键阶段的转化与漏损。

**所需字段**（可两形态）
- 形态一（宽表）：`stage`（阶段名）、`count`（该阶段人数/次数）
- 形态二（事件）：`user_id`、`stage`、`stage_date`

**计算口径**：按预设阶段顺序（见 `params.stage_order`）计算各级人数与转化率。

**输出指标**：阶段人数、逐级转化、整体转化、漏损最大阶段。

**业务解读**：针对最大漏损阶段设计干预（如报价→成交低，强化销售跟进）。

## 9. 购物篮 / 关联分析

**用途**：挖掘商品共现与关联规则，用于搭配推荐、陈列。

**所需字段**
- `order_id`：交易/购物篮标识
- `product`：商品（可每行一个商品，同一 order_id 多条）

**计算口径**
- 支持度 support = 含 X 的篮 / 总篮数
- 置信度 confidence = 含 X∩Y / 含 X
- 提升度 lift = confidence(X→Y) / support(Y)
- 输出 Top 关联规则（按 lift 排序）。

**输出指标**：热门单品、Top 关联规则表（前项→后项，support/confidence/lift）。

**业务解读**：lift>1 且置信度高的规则可用于"买了 A 的人也买了 B"推荐。

---

## 10. ABC 帕累托分析

**用途**：按贡献度把客户/商品分为核心(A)、重要(B)、长尾(C)。

**所需字段**
- `id`：`customer_id` 或 `item`（二选一，由 `params.id_type` 决定）
- `value`：贡献指标（金额/利润）

**计算口径**
- 按 value 降序，累计占比：A=前 70%、B=70%–90%、C=90%–100%（阈值可由 `params` 调整）。

**输出指标**：A/B/C 各类数量、累计贡献、集中度（如 A 类客户数占比 vs 金额占比）。

**业务解读**：用少量资源服务好 A 类；C 类考虑自动化/低成本运营。

---

## 11. NPS 净推荐值

**用途**：衡量客户忠诚度与口碑意愿。

**所需字段**
- `score`：0–10 整数（推荐意愿打分）

**计算口径**
- 推荐者(9–10)、中立(7–8)、贬损者(0–6)
- NPS = 推荐者% − 贬损者%

**输出指标**：NPS 值、三类占比、分布直方图数据。

**业务解读**：NPS 提升 1 点常对应显著营收增长；结合开放文本可定位体验痛点。
